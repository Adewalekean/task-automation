# Task Automation Using Bash Scripting

## Project Overview

This project is about using Bash scripting to automate basic tasks that I would normally have to do manually on the terminal.

The main aim was to get more comfortable writing Bash scripts, working with files and directories, checking system resources, using functions, and handling errors properly.

I completed this project on my Mac using VS Code and the terminal. Since some Linux commands are different on macOS, I had to make a few adjustments along the way.

- Bash
- VS Code
- Terminal
- Git and GitHub

## Task 1: Automating Directory and File Creation

For the first task, I created a Bash script called `create_files.sh`.

The script automatically creates three directories: `logs`, `reports`, and `backups`. It also creates a report file, adds content to it, and generates a log file using the current date and time.

I used `mkdir -p` to make sure the script would not fail if the directories already existed. I also added an `if` statement to check whether the report file was already created before writing to it.

### Commands Used

```bash
chmod +x scripts/create_files.sh
./scripts/create_files.sh
```

### Challenge I Faced

After running the script successfully, I noticed that the directories were not showing inside my project folder in VS Code.

I later discovered that the `BASE_DIR` variable was pointing to `$HOME/task-automation/workspace`, while my actual project was saved on my Desktop.

This caused the script to create another `task-automation` folder in my home directory.

### How I Fixed It

I changed the script to detect its location automatically instead of using a fixed path.

```bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
BASE_DIR="$(dirname "$SCRIPT_DIR")/workspace"
```

After making this change, I ran the script again and the directories were created in the correct project folder.

I also ran the script more than once to confirm that it recognised existing files instead of overwriting them.

**Result:** The script worked successfully and the directory creation process was automated.

## Task 2: Building a System Health Monitor

For this task, I created `system_monitor.sh` to check the health of my Mac.

The script displays the hostname, current date, disk usage, memory information, and the top five processes using the most CPU.

I also added conditions to check disk usage and memory pressure against an 80% threshold.

### Commands Used

```bash
chmod +x scripts/system_monitor.sh
./scripts/system_monitor.sh
```

### Challenges I Faced

**1. Running the script from the wrong directory**

At first, I was already inside the `scripts` folder when I tried to run:

```bash
./scripts/system_monitor.sh
```

This returned a file or directory not found error.

I realised that I was using the wrong relative path. I used `cd ..` to return to the main project directory and ran the command again. This time it worked.

**2. Unable to retrieve memory information**

My disk monitoring worked fine and showed 4% usage, which was below the 80% threshold.

However, when I added memory monitoring, the script kept displaying an error saying it could not retrieve memory information.

I tested the `memory_pressure` command separately and discovered that my Mac displayed:

```text
System-wide memory free percentage: 61%
```

But my script was searching for `System-wide free memory percentage`.

The words were in a different order, so the script could not find the value.

I corrected the `awk` command:

```bash
FREE_MEMORY=$(memory_pressure | awk '/System-wide memory free percentage/ {gsub(/%/, "", $NF); print $NF}')
```

After making this change, the script successfully retrieved the memory information and checked it against the threshold.

I also tested exit codes using `$?`, and the script returned `0` after successful execution.

**Result:** The system monitor successfully displayed system information and checked disk and memory conditions.

## Task 3: Refactoring Scripts Using Functions

In this task, I worked on making my scripts more organised by using functions.

I created two files:

- `functions.sh` — contains reusable functions for logging messages, checking disk usage, and checking memory pressure.
- `run_monitor.sh` — loads those functions and runs the health checks.

I used `local` variables inside functions and passed threshold values using `$1`.

I also used `source` to load the functions from another Bash file.

### Commands Used

```bash
chmod +x scripts/run_monitor.sh
./scripts/run_monitor.sh
echo $?
```

### Testing the Script

The first test ran successfully with the disk and memory thresholds set to 80%. The script returned exit code `0`.

To make sure the warning conditions worked, I temporarily changed both thresholds to 1%.

```bash
DISK_THRESHOLD=1
MEMORY_THRESHOLD=1
```

When I ran the script again, it displayed warning messages and returned exit code `1`.

I then changed the thresholds back to 80%, ran the script again, and got exit code `0`.

**Result:** The functions worked correctly and the script was able to report both successful checks and warning conditions.

## Task 4: Input Validation and Script Safety

For this task, I created `safe_automation.sh`.

The aim was to make the script handle incorrect inputs, prevent unwanted file changes, and respond properly when interrupted.

I used the following safety settings:

```bash
set -e
set -u
set -o pipefail
```

I also added input validation to make sure a directory path was provided before the script continued.

### Commands Used

```bash
chmod +x scripts/safe_automation.sh
./scripts/safe_automation.sh
./scripts/safe_automation.sh workspace/safe-test
```

### Testing

I tested the script in different ways.

**Test 1: Running without an argument**

The script displayed an error asking for a directory path and returned exit code `1`.

**Test 2: Running with a valid directory**

The script created the directory and an `automation.txt` file successfully. It returned exit code `0`.

**Test 3: Running the same command again**

The script recognised that the directory and file already existed and did not overwrite them.

**Test 4: Testing interruption handling**

I temporarily added a `sleep 30` command to give myself time to interrupt the script.

While the script was running, I pressed `Ctrl + C`.

The interruption handler displayed the cleanup message and the script returned exit code `130`.

After the test, I removed the temporary sleep command.

**Result:** The script successfully handled valid inputs, invalid inputs, repeated execution, and interruption signals.

## How to Run the Project

Clone the repository and enter the project directory.

```bash
git clone <repository-url>
cd task-automation
```

Make the scripts executable:

```bash
chmod +x scripts/*.sh
```

Run the directory automation script:

```bash
./scripts/create_files.sh
```

Run the system health monitor:

```bash
./scripts/system_monitor.sh
```

Run the function-based monitoring script:

```bash
./scripts/run_monitor.sh
```

Run the safe automation script:

```bash
./scripts/safe_automation.sh workspace/safe-test
```

To check the exit code after running a script:

```bash
echo $?
```

**Note:** The monitoring scripts were written and tested on macOS. Some commands, especially `memory_pressure`, would need to be changed when running the project on Linux.
